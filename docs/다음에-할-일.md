## 2026-09-02 에 한 일

### 두 번째 길찾기부터 카카오맵이 안 열리던 문제

증상 — 처음 들어와 길찾기를 하면 카카오맵이 열린다. 다시 나와서 다른
곳을 눌러 길찾기를 하면 `연결중입니다` 화면에 갇힌 채 카카오맵 설치
안내만 뜬다(applink.map.kakao.com).

**두 가지가 겹쳐 있었다. 첫 고침만으로는 안 나았다.**

**하나 — 서버 기록을 기다린 뒤에 열고 있었다.**
`await startTrip(...)` 이 누르는 순간과 카카오맵 사이에 끼어 있었다.
그 사이에 브라우저가 '사용자가 누른 순간'이 아니라고 보고 앱 열기를 막는다.
두 번째부터 안 되는 까닭도 여기 있다. 두 번째 `start_trip` 은 이미 가는
중인 기록을 취소하는 일이 하나 더 붙어 더 느리다.
고침 — 길찾기를 먼저 열고 기록은 뒤에서 따라가게 했다. `start_trip` 은
supabase 라이브러리를 거치지 않고 직접 부른다(동적 import 가 한 박자
늦기 때문). 페이지가 넘어가면 요청이 취소되므로 `keepalive` 를 붙였다.

**둘 — 코드가 페이지를 넘기고 있었다(이게 진짜 원인).**
`window.location.href = ...` 는 안드로이드 브라우저가 '사람이 누른 것'으로
쳐주지 않는다. 사람이 직접 누르는 `<a href>` 링크가 브라우저가 앱 열기를
가장 너그럽게 허용하는 길이다.
고침 — `길찾기` 를 `<a href target="_blank">` 로 바꿨다. 새 탭으로 여는
것도 일부러다. 예전에는 우리 화면이 카카오맵 주소로 덮여서 돌아오려면
`뒤로` 를 눌러야 했고, 두 번째 시도는 '같은 곳으로 또 넘어가려는 것'으로
취급됐다. 이제 우리 화면이 그대로 남는다.

**교훈** — 사용자가 누른 순간에 해야 할 일은 기다리지 말고 그 자리에서
곧바로 한다. 소리로 듣기에서도 같은 함정에 걸렸었다(8/25). 그리고
바깥 앱을 여는 일은 코드로 넘기지 말고 진짜 링크로 만든다.

실기기 확인 완료. 시험 4개(`test/start-trip.test.js`)를 붙여 고정했다.

  `길찾기`·`가족에게 알리기` 가 나온다. 목록 순서는 바뀌지 않는다.
  예전에는 누른 것을 맨 위로 끌어올려서 화면이 통째로 뒤바뀌었다.
- 목록 위에 `총 122개` 와 `거리순 ▾` 을 넣었다. 총 개수는 이미 칩에
  쓰던 값이라 서버를 더 다녀오지 않는다.
- 즐겨찾기 별표를 넣었다. 폰 안에만 저장하고 서버로 보내지 않는다.
  어느 대피소를 자주 보는지는 사는 곳을 짐작하게 하는 정보다.
- 동네 검색칸을 지도 위로 올렸다. 화면이 짧아져 목록이 더 빨리 보인다.
- 보여주는 줄을 10개에서 50개로 늘렸다. 서버가 이미 50곳을 보내주고
  있어서 통신량은 그대로다. 미뤄뒀던 '50곳 대신 10곳만 받기' 는 포기했다.

겪은 함정 셋.

**하나 — 옛 CSS 규칙이 새 규칙을 이겼다.** `.row{display:flex}` 가 남아
있어서 줄이 가로로 481px 까지 늘어나 별표가 화면 밖으로 밀려났다.
옛 규칙을 지우고 새 규칙에 `display:block` 을 못박았다.

**둘 — `총 122개` 가 `총 50개` 로 나왔다.** 칩 개수가 늦게 도착하는데
목록 머리말을 다시 그리지 않았다. 그때 `draw()` 를 함께 부른다.

**셋 — 재보니 어르신 기준을 어긴 곳이 아홉이었다.** 정렬 단추 44px,
검색칸과 찾기 단추 46px (56px 기준 미달). 파란 글씨 셋이 대비 5~6
(7 기준 미달). 빈 별표는 대비 1.36 으로 사실상 안 보였다.
전부 고쳐 지금은 밝은 화면·어두운 화면 모두 글씨 7 이상이다.

**폰에서 확인 완료.** 줄을 펼쳐 `길찾기` 를 누르면 카카오맵이 열리고,

## 2026-08-31 저녁에 한 일

### 지도가 안 나오던 문제 (컴퓨터에서만)

폰은 되는데 컴퓨터에서만 지도가 안 나왔다. 원인이 둘이었다.

**하나 — 한 번 숨기면 다시 안 나왔다.**
카카오가 준비되기 전에 그리려 하면 지도를 숨기는데, 나중에 준비돼도
다시 보여주는 곳이 없었다. `hideMap()` 만 있고 짝이 없었다.
폰은 위치를 찾는 사이 지도가 준비돼서 안 걸렸고, 컴퓨터는 저장해 둔
동네로 곧바로 그리려다 걸렸다. `showMap()` 을 만들어 짝을 맞췄다.

**둘 — 타일이 어긋났다.**
숨겨진 칸(높이 0)에 지도를 만들면 카카오가 자기 크기를 0 으로 기억한다.
나중에 보여줘도 그 크기 그대로라 전국 지도가 조각으로 붙어 보였다.
지도를 만들기 전에 먼저 칸을 보이게 하고, 그린 뒤 `relayout()` 을 부른다.
`relayout()` 은 `map.js` 에 있었지만 아무 데서도 부르지 않던 죽은 함수였다.

### 무엇을 눌러야 할지 헷갈리던 문제

스크롤하면 종류 넉 칸과 아래 띠가 나란히 놓여 누를 수 있는 네모가
여섯 개로 보였다. 넷은 **고르는 것**, 둘은 **하는 것**인데 구분이 안 됐다.

- `가족에게 알리기` 를 아래 띠에서 빼서 카드 안 `길찾기` 밑으로 옮겼다.
  코드상 원래부터 맨 위 카드의 그 대피소를 알리는 것이었다.
  화면 전체 띠에 떠 있어서 자기 자리를 못 찾고 있던 셈이다.
  아래 띠에는 `소리로 듣기` 하나만 남는다.
- 아래 띠 위쪽에 선을 넣어 다른 층임을 보였다.
- 종류 칸의 그림에서 상자를 벗겨 단추처럼 보이지 않게 했다.
  고른 것만 파란 상자가 씌워진다.
- 좁은 폰(420px 이하)에서 숨겨두던 '원하는 시설을 선택하세요' 를 되살렸다.
  스크롤하면 제목이 위로 사라져 그림 넉 개만 남는 것이 헷갈림의 뿌리였다.

**덤 — 어두운 화면에서 '대피소 종류' 제목이 안 보였다.**
밝은 화면용 남색(#243849)이 그대로 남아 대비가 1.36 이었다. 사실상 안 보인다.

| 1,000건 | 0 | 10초 | 초당 94건 |

**어느 수준에서도 실패 0건.** 서버가 오류를 내거나 멈추지 않는다.
600건부터 10초가 걸리는데, 600과 1,000이 똑같이 10초인 것으로 보아
서버가 아니라 **재는 쪽 컴퓨터의 한계**일 수 있다. 한 대에서 연결
1,000개를 동시에 여는 것 자체가 무리다. 진짜 한계는 더 위일 수 있다.

인원 조회(`shelter_counts`)는 응답이 **2바이트**뿐이고 초당 169건까지
처리한다. 2,000명이 앱을 켜두고 20초마다 물어봐도 초당 100건이라 여유가 있다.

정리 — **동시 접속 2,000명은 무리 없다.** 다만 2,000명이 똑같은 순간에
누르는 것은 재보지 않았고, 그때는 여러 초를 기다리게 된다.
실제 재난에서는 몇 분에 걸쳐 들어오므로 현실적인 걱정은 아니다.

### 무료 요금제가 걸리는 지점

평상시에는 문제없다. 월 32만 번은 도봉구 구민 31만 명이 한 달에
한 번씩 써야 겨우 닿는 수다.

문제는 진짜 재난 때다. 전국 규모 사건이면 하루에 한 달치를 쓸 수 있고,
그러면 월말까지 새로 못 찾는다. 대피소 앱이 정작 필요할 때 안 되는 것이
제일 나쁜 고장 방식이다. 다만 서버가 안 되면 지난번 목록을 대신
보여주도록 이미 만들어놨으므로 화면이 아주 죽지는 않는다.

손댈 방법 셋. 값싼 것부터.

1. **서버가 50곳 대신 10곳만 보내기** (5분, 공짜)
   월 32만 → 160만 번. 대신 목록도 10줄로 줄어든다.
2. **대피소 자료를 고정 파일로 옮기기** (하루 이틀, 공짜) ← 권함
   대피소 목록은 1년에 한두 번만 바뀌는 고정 자료다. 지역별로 잘라
   앱 파일처럼 올려두면 통신량이 월 100GB 짜리 다른 주머니로 옮겨간다.
   서버는 '몇 명이 가는 중'만 맡는다. 덤으로 서버가 죽어도 대피소
   검색은 계속 된다. 재난 앱에 그게 큰 값어치다.
3. **Supabase 유료** (월 3만 5천 원)
   통신량 50배, 멈춤 없음, 기계도 빨라진다.

**언제 손댈까** — Supabase 화면에서 이번 달 사용량을 본다.
한 달에 15만 번(절반)을 넘기기 시작하면 그때 2번을 하면 된다.
지금은 그대로 두고 지켜보는 것이 맞다.

### 1. 데이터 갱신 (연 1~2회면 충분하다)

```
node --env-file=.env scripts/import-api.mjs earthquake
node --env-file=.env scripts/import-api.mjs heat_cold
node --env-file=.env scripts/import-api.mjs temp_housing
node scripts/build-upload-csv.mjs
```

민방위는 localdata.go.kr CSV 라 방식이 다르다. 8/25 기록 참고.

**침수 -> 임시주거로 대체함.** 전국 단위 '침수 대피소' 공식 데이터가
존재하지 않는다. 침수는 지자체가 각자 관리해서 전국을 모아둔 곳이 없다.
대신 이재민 임시주거시설(수해로 집을 잃었을 때 머무는 학교 체육관 등)을
쓴다. 종류 키를 `flood` -> `temp_housing`, 칩 이름을 '침수' -> '임시주거'
로 바꿨다. DB 제약도 `supabase/migrate-temp-housing.sql` 로 함께 바꿨다.

주의: data.go.kr 의 `행정안전부_이재민임시주거시설정보`
(https://www.data.go.kr/data/15124965/fileData.do) 는 **쓸 수 없다.**
받아서 열어보니 51행짜리 시도별 통계표였다. "서울특별시 1191개소" 같은
합계만 있고 시설명·주소·위경도가 없어 지도에 찍을 수 없다.
개별 위치가 있는 데이터는 safetydata.go.kr 쪽에서 신청해야 한다.

data.go.kr 파일데이터 다운로드 방법(자동화용):
1. POST /tcs/dss/selectFileDataDownload.do
   (publicDataPk, publicDataDetailPk=uddi:..., fileDetailSn, publicDataTyCode=PR0051)
   -> 응답 JSON 의 atchFileId 가 진짜 파일 ID
2. POST /cmm/cmm/fileDownload.do (atchFileId, fileDetailSn)
상세 페이지 HTML 에 처음 보이는 FILE_... 은 설명서 PDF 라 함정이다.

## 미뤄둔 것

**카카오톡 안에서 소리 내기** — 카카오톡 인앱 브라우저는 Web Speech API
를 막는다. 대신 큰 글씨로 보여주고 `크롬에서 열기` 버튼을 제공한다.

진짜 소리를 내려면 미리 만든 음성 파일(mp3/wav)을 재생해야 한다.
윈도우에 한국어 음성 엔진(Microsoft Heami)이 있어 무료로 만들 수 있음을
확인했다. 다만 대피소 이름 17,228개는 미리 녹음할 수 없어
"걸어서 N분입니다" 같은 부분만 소리로 낼 수 있다.
WAV 크기는 8kHz 기준 문장당 약 80KB. 압축 도구(ffmpeg 등)는 없다.

필요해지면 이 조사 결과부터 다시 보면 된다.
