# 대피소 목록 화면 다시 만들기

작성: 2026-09-01
바탕: 더벤티 픽업 매장 선택 화면 (사진 없이)

## 왜 바꾸는가

지금 목록은 두 가지 모양이 섞여 있다. 맨 위 한 곳만 큰 카드고, 나머지는
작은 줄이다. 다른 곳을 고르면 그 줄이 맨 위로 올라가 큰 카드가 되고,
원래 있던 곳은 작은 줄로 내려간다. 화면이 통째로 뒤바뀌어서 어르신은
방금 무엇을 눌렀는지 놓친다.

또 목록에서 할 수 있는 일이 없다. 대피소마다 `길찾기` 를 누르려면 먼저
그 줄을 눌러 맨 위로 올린 다음, 화면을 위로 올려서 카드를 찾아야 한다.

모든 줄을 같은 모양으로 맞추고, 누른 줄이 제자리에서 펼쳐지게 한다.
화면이 뒤바뀌지 않으므로 방금 누른 곳을 눈으로 계속 좇을 수 있다.

## 무엇을 만드는가

### 목록 줄

한 줄에 담기는 것.

| 자리 | 내용 | 비고 |
| --- | --- | --- |
| 첫 줄 | 이름 + 거리 | 거리는 파란 글씨 |
| 둘째 줄 | 주소 | 넘치면 잘라낸다 |
| 셋째 줄 | 인원 배지 | 늘 보인다. 0명이어도 보인다 |
| 셋째 줄 | `가장 가까운 곳` 딱지 | 가장 가까운 한 줄에만 |
| 오른쪽 | 별표 | 누르면 즐겨찾기 |

줄을 누르면 그 자리에서 아래로 `길찾기` 와 `가족에게 알리기` 가 펼쳐진다.
한 번에 하나만 열린다. 다른 줄을 누르면 앞의 것은 접힌다.

첫 화면에서는 맨 위 한 줄이 열려 있다. 아무것도 누르지 않고 바로
`길찾기` 를 누를 수 있어야 한다. 지금도 그랬고, 재난 상황에서 한 번이라도
덜 누르는 것이 낫다.

**목록은 순서를 바꾸지 않는다.** 누른 줄은 제자리에 그대로 있고 펼쳐지기만
한다. 지금처럼 맨 위로 끌어올리지 않는다.

### 인원 배지

셋째 줄의 배지 문구.

| 상황 | 문구 |
| --- | --- |
| 0명 | `가는 사람 없음` |
| 1명 이상 | `3명 가는 중` |
| 나 혼자 | `나 혼자 가는 중` |
| 나 포함 여럿 | `3명 가는 중 (나 포함)` |

0명일 때와 사람이 있을 때 배지 색을 달리한다. 색만으로 구분하지 않도록
문구 자체가 다르다.

집계가 잘못되어 음수가 들어와도 `가는 사람 없음` 으로 본다. 지금
`peopleText` 가 그렇게 하고 있고 시험으로 고정돼 있다. 그대로 지킨다.

### 총 개수와 정렬

목록 위에 `총 122개` 와 `거리순 ▾` 을 좌우로 놓는다.

`총 122개` 는 이미 종류 칩에 쓰고 있는 `nearby_counts` 값을 그대로 쓴다.
서버에 새로 물어보지 않으므로 통신량이 늘지 않는다.

반경 안에 50곳이 넘게 있으면 목록에는 50곳까지만 나온다. 그때는 목록
맨 끝에 흐린 글씨로 `가까운 50곳만 보여드립니다` 를 붙인다. 총 개수와
목록 길이가 다른 이유를 화면 안에서 알 수 있어야 한다. 50곳 이하면
이 문구는 나오지 않는다.

정렬은 두 가지다.

- `거리순` — 가까운 순. 처음 값.
- `즐겨찾기순` — 별 단 곳이 먼저, 그 안에서 가까운 순.

고른 순서는 폰에 기억해 다음에 열 때도 유지한다.

**정렬 단추는 브라우저 기본 `<select>` 로 만든다.** 겉모양만 알약처럼
꾸민다. 직접 만든 팝오버보다 나은 이유가 셋이다. 폰에서 화면 아래쪽에
큰 목록이 올라와 어르신이 누르기 쉽다. 화면 읽어주기가 공짜로 된다.
코드가 적어 고장 날 곳이 적다. 더벤티의 팝오버와 생김새는 다르지만
쓰기에는 더 낫다.

### 즐겨찾기

별을 누르면 그 대피소를 폰에 저장한다. 다시 누르면 지운다.

**서버로 보내지 않는다.** 누가 어느 대피소를 자주 보는지는 사는 곳을
짐작하게 하는 정보다. 지금 앱은 로그인이 없어 기기 하나가 곧 사람
하나이므로, 서버에 쌓으면 그대로 개인 기록이 된다. 즐겨찾기는 폰을 바꾸면
사라지는 편의 기능으로 둔다.

### 검색칸을 지도 위로

`다른 동네로 찾기` 의 입력칸과 `찾기` 단추를 지도 왼쪽 위에 얹는다.
지금 그 자리에 있는 `● 내 주변 지도` 라벨은 없앤다. 알려주는 것이 없다.

지도 아래에는 나머지를 남긴다. 안내 제목, 설명, 오류 문구,
`현재 위치 다시 찾기`. 이것들까지 지도 위에 욱여넣으면 글씨가 작아진다.
이 부분은 위치를 모를 때만 보인다.

**함정 하나.** 지금 CSS 에 `.map-frame:has(.map--hidden){display:none}` 이
있어서 지도가 숨겨지면 지도 틀 전체가 사라진다. 검색칸을 그 안에 넣으면
카카오가 안 뜰 때 동네 검색까지 같이 사라진다. 이 규칙을 지우고
`.map--hidden{display:none}` 만 남겨, 지도 그림만 사라지고 틀과 검색칸은
남게 한다.

### 몇 줄까지 보여주는가

**50줄 모두.** 서버 함수 `nearby_shelters` 가 이미 50곳을 보내주고 있으므로
50줄을 다 그려도 통신량은 지금과 같다. `총 122개` 라고 써놓고 10줄만
보여주면 앞뒤가 맞지 않는다.

미뤄뒀던 "50곳 대신 10곳만 받아 통신량 5배 아끼기" 는 포기한다. 통신량이
정말 모자라지면 그때 다시 본다.

## 어떻게 만드는가

### 새 파일

**`src/favorites.js`** — 즐겨찾기를 폰에 넣고 뺀다.

```
readFavorites(storage) -> Set<id>
toggleFavorite(id, storage) -> Set<id>     저장까지 하고 새 Set 을 돌려준다
```

`location.js` 의 `savePlace` / `readSavedPlace` 와 같은 모양으로 만든다.
저장 공간이 부족하거나 브라우저가 막아도 던지지 않는다. 즐겨찾기가
안 되는 것이 대피소를 못 보는 것으로 번지면 안 된다.

**`src/sorting.js`** — 목록 순서를 정한다.

```
sortShelters(shelters, { sort, favorites }) -> 새 배열
```

어느 쪽이든 **늘 새 배열을 돌려준다.** 원본은 건드리지 않는다.
`거리순` 은 서버가 이미 정렬해 보내주므로 순서를 그대로 두고 베끼기만 한다.
`즐겨찾기순` 은 별 단 것을 앞으로 보내고, 같은 무리 안에서는
`distance_m` 오름차순이다.

순수 함수라 화면 없이 시험할 수 있다.

### 고치는 파일

**`src/constants.js`** — `STORAGE_KEYS` 에 `favorites`, `sort` 를 더한다.

**`src/ui.js`** — `renderList` 를 다시 만든다.

지금 `renderList` 는 인자가 여섯 개다. 여기에 펼침·즐겨찾기·총개수·정렬을
더하면 열 개가 된다. 순서를 헷갈리기 쉽다. 객체 하나로 묶는다.

```
renderList({
  shelters, counts, notice, total, sort,
  openId, favorites, activeShelterId, nearestId,
  handlers: { onGo, onShare, onToggleOpen, onToggleFavorite, onChangeSort },
})
```

부르는 곳이 `draw()` 한 곳뿐이라 바꾸는 부담이 없다.

안을 셋으로 쪼갠다. 각각 하는 일이 하나씩이다.

- `listHeader(total, sort, onChangeSort)` — 총 개수와 정렬 단추
- `shelterRow(shelter, 상태, handlers)` — 줄 하나
- `rowActions(shelter, handlers)` — 펼쳐졌을 때의 두 단추

`topCard` 와 `summaryRow` 는 없앤다.

`peopleText` 는 `peopleBadgeText` 로 이름을 바꾸고 문구를 짧게 한다.
지금 문구 `지금 이곳으로 가는 사람은 없습니다` 는 배지에 넣기에 길다.
`test/people-text.test.js` 도 같이 고친다.

**`src/main.js`** — 상태에 셋을 더한다.

```
state.sort       'distance' | 'favorite'
state.openId     펼쳐진 줄의 id. 없으면 null
state.favorites  Set<id>
```

`onSelect` 은 없앤다. 대신 `onToggleOpen(shelter)` 이 `state.openId` 만
바꾼다. 목록 순서를 건드리지 않으므로 화면을 위로 밀어 올리는
`window.scrollTo` 도 없앤다.

`currentShelter()` 는 "펼쳐진 줄, 없으면 첫 줄" 로 바꾼다. 바닥의
`소리로 듣기` 가 이 값을 쓴다. 지금은 늘 첫 줄이었다.

새로 검색할 때마다 `state.openId` 는 첫 줄로 되돌린다. 종류를 바꿨는데
없어진 대피소가 펼쳐진 채로 남으면 안 된다.

**`index.html`** — 검색 입력칸과 `찾기` 단추를 `.map-frame` 안으로 옮긴다.
`.map-frame__label` 을 지운다.

**`style.css`** — 줄·배지·별표·정렬 단추·지도 위 검색칸의 모양.
`.map-frame:has(.map--hidden)` 규칙을 지운다.

### 어르신 기준은 그대로 지킨다

- 본문 18px 이상, 대피소 이름 20px 이상
- 누르는 곳 56px 이상 — **별표도 포함한다.** 별 그림은 작아도 누르는
  범위는 56px 이어야 한다. 옆의 줄을 잘못 누르면 엉뚱한 곳이 펼쳐진다.
- 대비 7:1 이상 — 배지의 글씨색과 배경색을 밝은 화면·어두운 화면
  양쪽에서 재서 확인한다
- 글자 크기 조절(`--fs`)이 새로 만드는 모든 글씨에도 걸려야 한다

## 시험

새로 만드는 순수 함수를 시험으로 고정한다.

**`test/favorites.test.js`**
- 처음에는 비어 있다
- 넣었다 다시 넣으면 빠진다
- 저장한 것이 다시 읽힌다
- 저장이 막혀도 던지지 않는다
- 망가진 값이 들어 있으면 빈 Set 을 돌려준다

**`test/sorting.test.js`**
- 거리순은 서버가 준 순서를 그대로 둔다
- 즐겨찾기순은 별 단 것을 앞으로 보낸다
- 별 단 것끼리는 가까운 순이다
- 별 없는 것끼리도 가까운 순이다
- 원본 배열을 건드리지 않는다
- 빈 배열이어도 터지지 않는다

**`test/people-text.test.js`** — 새 문구에 맞춰 고친다.

화면을 그리는 부분은 지금도 시험하지 않는다. 브라우저에서 눈으로
확인하고 폰에서 다시 본다. 이번에도 같게 한다.

## 하지 않는 것

- **사진** — 회성 님이 빼자고 하셨다. 대피소 사진은 있지도 않다.
- **즐겨찾기를 서버에 저장** — 위 이유.
- **`더 보기` 단추와 무한 스크롤** — 50줄이면 충분하다.
- **인원순·수용인원순 정렬** — 멀리 있는 곳을 맨 위로 올려 오히려
  위험할 수 있다.
- **지도와 목록 연동 개선** — 줄을 펼치면 지도가 그곳으로 움직이는 것.
  있으면 좋지만 이번 일이 아니다. 다 만든 뒤에 따로 본다.

4. 폰에서 직접 본다 — 별표 누르기, 정렬 바꾸기, 줄 펼쳐서 길찾기
